# Хранилище и две репы

```
pdd-trainer/                 ← публичная репа (GitHub Pages): только загрузчик и зашифрованное приложение
├─ index.html, login.js, gate.css, sw.js, vault-crypto.js, vault.html, vault-panel.js, 404.html
├─ vault/                    ← зашифрованное приложение — коммитится сюда
├─ tools/vault.py, serve.py, pre-commit
├─ secrets/                  ← пароль хранилища (в .gitignore — никуда не попадает)
├─ assets/                   ← видео, транскрипции, скриншоты курса (в .gitignore)
└─ app/                      ← исходники: в .gitignore публичной репы, это отдельная ПРИВАТНАЯ репа
```

Папка `app/` — расшифрованный код. Публичная репа её не видит (`app/` в `.gitignore`), поэтому внутри можно держать свою
приватную git-репу. `tools/vault.py` и панель пропускают папки `.git` — служебные файлы приватной репы не шифруются
и при расшифровке не трогаются.

## Один раз: приватная репа для исходников

1. На GitHub: New repository → **Private**, имя например `pdd-trainer-src`, без README и .gitignore.
2. В папке `app/`:

   ```
   cd app
   git init -b main
   git add .
   git commit -m "ПДД-тренажёр: исходники 0.3"
   git remote add origin https://github.com/so1ow4y/pdd-trainer-src.git
   git push -u origin main
   ```

Публичная репа (`pdd-trainer`) остаётся как есть: коммиты и push — из корня проекта.

## Каждый раз: правка → шифрование → публикация

```
cd app
git add . && git commit -m "…" && git push      # исходники — в приватную
cd ..
python tools/vault.py status                    # что изменилось в app/ по сравнению с vault/
python tools/vault.py encrypt                   # app/ → vault/ (шифруются только изменённые файлы)
git add -A && git commit -m "…" && git push      # зашифрованное — в публичную
```

Пароль `vault.py` берёт из переменной `PDD_VAULT_PASSWORD`, иначе из `secrets/vault-password.txt`, иначе спрашивает.

Чтобы не закоммитить в публичную репу устаревший `vault/`, поставьте проверку перед коммитом:

```
cp tools/pre-commit .git/hooks/pre-commit
```

## На новом компьютере

```
git clone https://github.com/so1ow4y/pdd-trainer.git
cd pdd-trainer
git clone https://github.com/so1ow4y/pdd-trainer-src.git app
```

Нет доступа к приватной репе — исходники можно достать из хранилища: положите пароль в `secrets/vault-password.txt`
(или введите, когда спросит) и выполните

```
python tools/vault.py decrypt          # vault/ → app/; --force — перезаписать отличающиеся, --clean — удалить лишние
```

## Команды tools/vault.py

| Команда | Что делает |
|---|---|
| `status` | Что изменилось в `app/` по сравнению с хранилищем (код выхода 1, если есть изменения) |
| `encrypt` | `app/` → `vault/`; неизменившиеся файлы сохраняют свои блобы. `--rekey` — новая соль (и пароль) |
| `decrypt` | `vault/` → `app/` |
| `verify` | Проверить пароль и наличие всех блобов; `--deep` — расшифровать всё и сверить sha256 |
| `passwd` | Сменить пароль: всё перешифровывается новым ключом, `secrets/vault-password.txt` обновляется |
| `genpass` | Придумать пароль (4 группы по 5 символов) и записать в `secrets/vault-password.txt` |
| `selftest` | Проверить AES-256-GCM на контрольных векторах NIST |

## Веб-панель (vault.html)

То же в браузере, без Python: 1) проверка пароля по опубликованному хранилищу; 2) в Chrome/Edge на компьютере — выбор папки
проекта: «Что изменилось», «Зашифровать app/ → vault/», «Расшифровать vault/ → app/», смена пароля; 3) в любом браузере —
«Скачать исходники (ZIP)» из хранилища сайта и «Зашифровать папку app/ в ZIP»; 4) «Выйти и стереть всё с устройства».

Адрес — `https://so1ow4y.github.io/pdd-trainer/`. Ссылка вида `…/app/#/lesson/lesson2` без входа ведёт на страницу входа

## Как устроено шифрование

- Ключ: PBKDF2-HMAC-SHA256 (пароль, случайная соль 16 байт, 600 000 итераций) → 64 байта: 32 — ключ AES-256-GCM, 32 — ключ HMAC.
- Каждый файл `app/` — AES-256-GCM со своим случайным IV; доп. данные — путь файла, поэтому блоб нельзя подсунуть под другим именем.
- Имя блоба — HMAC от пути: по имени не понять, что это за файл.
- Оглавление (пути, размеры, sha256, типы) зашифровано тем же ключом. Открыт только `vault.json`: соль, число итераций, IV оглавления.
- Пароля и хеша нет нигде: неверный пароль просто не проходит проверку GCM. Подмена ключа в коде ничего не даёт — расшифровать
  можно только настоящим ключом, а он получается только из пароля.
- После входа ключ — неэкспортируемый `CryptoKey` в IndexedDB этого сайта: его нельзя прочитать даже скриптом страницы.

Что видно постороннему: что это зашифрованный ПДД-тренажёр, сколько файлов и какого они размера, когда хранилище менялось.
Единственная атака — перебор пароля офлайн; сгенерированный пароль (20 символов из 55) перебрать нереально, а свой
придумывайте не короче 12 символов.

Пароль потерян — хранилище не расшифровать никак. Исходники останутся в приватной репе; зашифруйте заново с новым паролем:
`python tools/vault.py encrypt --rekey`.
